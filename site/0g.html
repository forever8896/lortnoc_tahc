0G · Confidential Compute

Intelligent AI for creating realistic conversation obfuscation.

Every message written several ways. Sealed compute picks the one that sounds most human.

Why we built on it

Natural Language Encryption turns a private message into small talk. That only protects anyone if the small talk is convincing — a sentence nobody would actually send is itself a flag, and being flagged is worse than sending in the clear.

So we write every message several ways and something has to pick the most natural one. That judge necessarily sees text derived from the user’s message.

Run it on an ordinary inference endpoint and we’d have manufactured the exact record this product exists to prevent. 0G’s confidential compute lets the judgement happen somewhere that can’t retain what it judged.

How it works here

  1. Encrypt. AES-SIV, client-side. Everything downstream sees ciphertext only.
  2. Write it several ways. A pinned local GPT-2 encodes that ciphertext into multiple different cover texts.
  3. Judge in sealed compute. 0G scores which candidate reads most like a person wrote it.
  4. Send the winner. That sentence about coffee is all the platform ever keeps.
  5. Decode. The other end reverses it exactly. A valid auth tag means it was ours — an invalid one means it really was small talk.

What 0G sees: candidate cover texts. Ciphertext, never plaintext, and useless without a key that never leaves the device.

For the 0G team

We asked whether we could deploy our own model into your TEE, and you told us straight that it isn’t supported yet. That answer shaped the architecture, and it shaped it for the better.

It forced a split we should have found on our own

Being told no made us work out which half of a steganographic codec actually needs determinism. The reversible arithmetic coding does — byte-identical distributions or the message is simply gone. The naturalness judgement doesn’t; it’s a preference between finished candidates that nobody ever has to reproduce.

Once that was clear, sealed inference was obviously the right home for the judge and obviously the wrong home for the coder. Determinism where reversibility needs it, sealed compute where privacy does. We wouldn’t have drawn that line as cleanly if the easy path had been open.

We’re using it as a judge, not a chatbot

Most confidential-inference demos are a private assistant. We’re using it as something narrower and stranger: a component that sees derived material, forms an opinion, returns a ranking, and keeps nothing.

We’d guess that wasn’t the headline use case you designed for. It worked anyway, which says more about how general the primitive is than any benchmark would.

The broker model is the part people will underrate

Routing inference through a broker that settles per request — provider signer acknowledged, every request signed — is what lets a product whose entire pitch is “don’t trust us” use hosted compute at all. We are honest about where we stop: we use the broker, we do not yet capture and verify a TEE attestation per response. The moment we do, a privacy claim becomes a privacy proof, and the fact that the path is already there is the point.

0G Chain carries the other half: the Semaphore membership contract, where paying inserts a commitment and claiming burns a single-use nullifier. wallet → commitment is public; commitment → handle is not.
